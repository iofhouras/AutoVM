Getting started

Three steps, and one of them is pressing a button

There is nothing to configure, no ISO to find, and no installer questions to answer.

1

Download and install

One installer, a few megabytes. It needs administrator rights because virtualization software installs a driver — that is the only prompt you will see.

2

Choose and type

Pick Kali Linux Virtual Machine, then type the username and password you want to sign in with inside it. AutoVM never stores that password.

3

Press Create VM Now!

Then leave it. AutoVM installs the hypervisor, fetches a verified image, runs the whole installation and proves the account works by signing in.

Every phase has to prove it worked before the next one starts — the hypervisor by reporting its version, the image by matching a checksum, the account by signing in. If a step cannot prove it, AutoVM stops and tells you which one, in plain words. Work already finished is recorded, so starting again continues rather than repeating.

It fits itself to your PC

You do not have to know how much memory to give it

AutoVM reads your computer and does the arithmetic. A machine that is too big makes Windows crawl; one that is too small will not run a desktop. Neither is something you should have to work out.

WhatHow AutoVM decides
Memory40 % of your PC's memory, rounded to a 512 MB step — never more than half, never above 8192 MB
ProcessorsHalf your logical cores, capped at 4
DiskUp to 60 GB, trimmed to fit your roomiest drive with 15 GB left for Windows
WhereThat drive — not blindly C:
SoftwareA lighter desktop set on a smaller PC, the full set on a larger one

After it is built

A place to run it from, and settings you can actually change

AutoVM does not disappear once the machine exists. It becomes the console for it — and it puts a shortcut on your desktop so you never need to open a terminal.

Power and state

Start it in a window or in the background. Shut it down cleanly, freeze it exactly as it is, or force it off when it stops responding.

Hardware

Change memory, processors, video memory and the shared clipboard. AutoVM refuses anything that would starve Windows, and explains why.

Restore points

Take a snapshot before you experiment, then roll the whole machine back to it. One is taken automatically the moment the build finishes.

Files and data

Share a Windows folder with the machine to move files in and out, open its folder on disk, or export the whole thing to a single file as a backup.

Before you start

What your PC needs

AutoVM checks every one of these before it changes anything, and tells you how to fix whatever is missing.

FirmwareHardware virtualization (Intel VT-x / AMD-V) switched on
Time30–90 minutes, mostly unattended
Virtualization switched off? That is the one thing AutoVM cannot fix from Windows. It will tell you so on the first screen, and point you at the setting in your firmware (usually F1, F2 or a Novo button at boot, under Security).

What it will and will not do

It is careful with the computer you already have

With your say-so

  • Installs Oracle VirtualBox and 7-Zip
  • Creates one virtual machine and its disk
  • Downloads a system image, and checks it against the publisher's own checksum before using it
  • Writes a control panel and a desktop shortcut
  • Removes existing machines only if you opt in and type DESTROY

Never

  • Touches your firewall
  • Disables virtualization-based security, Memory Integrity or WSL2 to make the guest faster
  • Works around driver signing — a blocked install is reported, not circumvented
  • Deletes WSL disks, recovery images, Windows.old or mounted disks
  • Keeps a copy of your password
Your machine can reach out; nothing can reach in. AutoVM gives the guest address-translated networking only — no port forwarding, no bridged adapter, no SSH server. That is what makes a simple password inside it acceptable. If you ever change that, change the password first.

Questions

Things worth knowing

Is this safe to run on my work laptop?

AutoVM is careful, but a managed device is a different question. Company policy often blocks the installation of kernel drivers, which is what a hypervisor needs. If that happens, AutoVM reports it as an environment problem and stops — it will not attempt to work around it.

Check with whoever manages the device before installing virtualization software on it.

Why does it ask for administrator rights?

VirtualBox installs kernel-mode drivers, which cannot be done without them. AutoVM asks once, at launch, rather than surprising you halfway through a build.

Where does the Kali image come from?

Straight from Kali's own mirror. AutoVM reads the current filename from the publisher's directory listing rather than hardcoding one — versions rotate quarterly and pinned names stop working — and verifies the download against the publisher's own SHA-256 before it is attached to anything. A mismatch deletes the file and stops the build.

My login has a capital letter. Does that work?

Yes, and it is handled properly. The Linux installer only accepts lowercase account names and quietly waits at a prompt when it gets anything else — the usual reason an unattended install appears to hang forever. AutoVM creates the account in lowercase, renames it once it exists, moves the home directory, repairs ownership, and then proves it by signing in as the name you asked for.

Remember that Linux logins are case-sensitive: you sign in with exactly what you typed.

What if I close the window halfway through?

Nothing is lost. Every phase records its outcome before the next one starts, so opening AutoVM again continues from the last completed step instead of starting over — and in particular it never repeats anything destructive.

How do I get rid of it all afterwards?

Delete the machine from the Files & data tab — it asks you to type the machine's name, then removes it and its disk. Uninstall AutoVM from Windows Settings, and uninstall VirtualBox the same way if you no longer want it.

Can I use it without the window?

Yes. The engine is a PowerShell module and the wizard is one caller. There is a console front end for scripted or repeated builds, and every command is documented in the repository.
