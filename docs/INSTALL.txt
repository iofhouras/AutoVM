AutoVM
======

AutoVM sets up a Linux virtual machine on this computer for you.

You choose a login and a password. AutoVM does the rest: it checks what this
machine can do, sizes the virtual machine to fit it, downloads a verified
system image, installs it without asking you installer questions, and leaves a
control panel on your desktop.


Before you start
----------------

  *  Administrator rights. Virtualization software installs a driver.
  *  About 45 GB of free disk space, and 6 GB of memory or more.
  *  Hardware virtualization enabled in your firmware (BIOS/UEFI). AutoVM
     checks this on the second screen and tells you how to fix it if it is off.
  *  A network connection. The system image is several gigabytes.
  *  Time. Expect 30 to 90 minutes, mostly unattended. Keep the computer awake
     and plugged in.


Using it
--------

  1.  Start AutoVM from the Start menu.
  2.  Choose "Kali Linux Virtual Machine".
  3.  Type the username and password you want to use inside the machine.
  4.  Press "Create VM Now!" and leave it running.
  5.  When it finishes, press "Manage my machine" - or use the AutoVM Control
      Center shortcut on your desktop.

Your login is case-sensitive inside Linux. If you type a capital letter, you
will need that capital letter to sign in.


Managing the machine afterwards
-------------------------------

The "My machines" screen inside AutoVM is where the machine lives once it
exists:

  Overview        start it in a window or in the background, shut it down,
                  save its state, or force it off if it stops responding
  Settings        memory, processors, video memory and the shared clipboard
                  (editable while the machine is shut down)
  Restore points  take a snapshot before you experiment, then roll the whole
                  machine back to it
  Files & data    share a Windows folder with the machine, open its folder on
                  disk, export it to a single file, or delete it

AutoVM opens straight onto this screen whenever a machine already exists.


What AutoVM will not do
-----------------------

  *  It does not change your firewall or your Windows security settings.
  *  It does not delete any virtual machine you already have, unless you turn
     that on and type DESTROY to confirm.
  *  It does not keep a copy of your password.
  *  It does not give anything on your network a way into the virtual machine.
     The machine can reach out; nothing can reach in. That is why a short
     password is acceptable - change it before switching the machine to
     bridged networking or forwarding a port into it.


Where things are
----------------

  Application        C:\Program Files\AutoVM
  Logs and state     C:\ProgramData\AutoVM\logs
  Downloaded images  C:\ProgramData\AutoVM\cache
  The machine        Wherever AutoVM told you it had the most room, usually
                     C:\AutoVM\Machines

Uninstalling AutoVM removes the application. It does not remove the virtual
machine, the downloaded image, or VirtualBox - delete those yourself if you
want the space back.


If something goes wrong
-----------------------

Every run writes a full log to C:\ProgramData\AutoVM\logs. The final screen
names the step that stopped and what to do about it. Starting AutoVM again
carries on from the last completed step rather than repeating work.
